# OCaml semantics and target representations

| OCaml declaration | Rust | C++ | Semantics to preserve |
| --- | --- | --- | --- |
| `type name = other` | `type Name = Other` | `using Name = Other` | An abbreviation is interchangeable with its target. If the domain needs a distinct type, call out the API change before introducing a newtype. |
| `type id = Id of int32` | A single-constructor variant can use `struct Id(i32)` | A `struct Id` wrapping `std::int32_t` with an explicit constructor | The declaration introduces a nominal type. Preserve the `Id` construction entry point when the constructor API matters. |
| `type mode = Read \| Write` | Payload-free `enum Mode` | `enum class Mode` | Assign stable exported numbers when the wire format or ABI specifies them. |
| `type t = Nil \| Add of expr * expr` | `enum T { Nil, Add(Expr, Expr) }` with indirection on edges as needed | A local `std::variant<Nil, Add>` value, or a `T` base with a kind and concrete leaves for an object family | Match each constructor and preserve the ability to construct the empty branch. |
| `A of int32 * bool` and `B of (int32 * bool)` | `A(i32, bool)` and `B((i32, bool))` | `A(int32_t, bool)` and `explicit B(std::pair<int32_t, bool>)` | `A` has two arguments. `B` has one argument containing a pair. Preserve the grouping when the pair is named by an alias, too. |
| `type point = { x : float; y : float }` and `P of { x : float; y : float }` | Named `struct Point` and a named-field variant `P { x, y }` | Plain struct and a payload struct or tagged leaf with the corresponding fields | Preserve field names. Keep an inline record scoped to its constructor by default. |
| `'a t` and `('a, 'b) t` | `T<A>` and `T<A, B>` | Class templates of the same arity, e.g. `template<class A, class B>` | Apply constraints where operations need them. A tag shared by multiple payload instantiations needs a domain that distinguishes them. See the [C++ guide](cpp.md). |
| `'a option` and `('a,'e) result` | `Option<A>` and `Result<A,E>` | `std::optional<A>` and, where supported, `std::expected<A,E>` or the project Result type | Preserve `None` and `Some None` as distinct values. Collapse an optional into a nullable pointer only when null encodes exactly one level of absence. |
| `'a list` and `'a array` | `Vec<A>` for sequential access, `&[A]` for borrowed arguments | `std::vector<A>` for owned sequences, `std::span<const A>` for borrowed arguments | A list is persistent. Preserve shared links when callers use constant-time cons or tail, tail sharing, or identity. Arrays support shared mutation and have fixed length. Restrict resizing when length is observable. |
| `type a = ... and b = ...` | Name both types in the module. Break by-value cycles using `Box`, shared handles, or IDs | Forward declare the types, order definitions by completeness requirements, and define destructors where the required types are complete | Every by-value cycle needs an indirect edge. A vector already provides one. `Option<T>` and `std::optional<T>` generally need the size of `T`. |
| `type 'a wrapper = { mutable value : 'a }` and `'a ref` | Use `&mut` for exclusive access. For observable shared updates, choose a handle suited to the thread model, e.g. `Rc<RefCell<_>>` | Give a unique owner controlled mutators, or have aliases refer to the same storage | Writes must be visible through every alias that can observe them in OCaml. Expose read-only payloads through read-only borrows. |
| `type t` and `private` declarations | Module-private fields or constructors with a controlled public API | Incomplete types, private constructors, or factories | Preserve the operations exposed by the `.mli`. An abstract name alone gives no information about its layout. |

## Scalars and borrowing

- Map `int32` and `int64` to Rust `i32` and `i64` or C++ `std::int32_t` and `std::int64_t`. OCaml `int` is a tagged machine integer, usually 31 or 63 bits including the sign on 32-bit or 64-bit hosts. Choose a target integer from the domain's range. When exact overflow behavior matters, specify the OCaml width and implement wrapping at that width. Rust `isize` and C++ `intptr_t` have different ranges from OCaml `int`. Use unsigned arithmetic in C++ to implement the required modular operations.
- Map `bool` and `float` to Rust `bool` and `f64` or C++ `bool` and `double`. OCaml `char` is one byte and maps to `u8` or `std::uint8_t`. OCaml strings can contain arbitrary bytes. Use Rust `String` when UTF-8 is guaranteed and `Vec<u8>` for byte strings. C++ `std::string` supports embedded NUL bytes. Preserve the length in borrowed views. Use `()` or `void` for unit returns and `()` or an empty struct when storing unit as a value.
- Use `Box` or `unique_ptr` for uniquely owned trees. Insert indirection on recursive Rust fields. A default-deleter `unique_ptr<Base>` needs to destroy derived objects correctly through the base. Establish non-null child invariants during construction. Identify the owner of each view. If a view is stored, account for mutation, reallocation, and lifetime.
- For DAGs, shared constants, or common subexpression elimination, use `Rc` / `Arc`, the host's intrusive handle, or `ExprId` plus a node table. Specify ID stability and address stability separately. Distinguish node storage (`IndexedMap<ExprId, Node>`) from an edge list (`vector<ExprId>`). Use generations when needed for deleted and reused slots. Across arenas or generic instantiations, establish ID provenance with a type brand, an instance identifier, or controlled construction. An append-only DAG can preserve acyclicity by accepting only edges to existing nodes in the same arena. Generate structural equality or ordering when callers need it. Define identity and pointer equality separately.
- In Rust, match on `&expr` or on an existing borrow. Add only the indirection recursion needs. Compile usage examples, including test requirements such as `Debug` for `assert_eq!`. Derive `Clone`, `Copy`, `Eq`, and `Hash` and add trait bounds according to use. A tree containing `f64` does not qualify for a derived `Eq`. Keep the default Rust representation for a local enum unless an ABI requires otherwise.

## Source types that need individual treatment

For GADT result indices and equality constraints, existential types, row constraints on open polymorphic variants, and `type t = ..` extensions, identify which static guarantees the target must preserve. A known closed row can map to a local enum. For an open row, preserve dispatch for both known and future cases. For first-class functions, account for captures, escaping closures, and the calling convention. If context is missing, identify the declaration, proposed representation, and guarantee that still needs a decision. Continue with ordinary declarations. Consult the [OCaml type declaration reference](https://ocaml.org/manual/5.3/typedecl.html) for the source syntax.
